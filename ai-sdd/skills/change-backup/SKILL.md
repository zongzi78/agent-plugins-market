# change-backup（改前留痕）

## 这是什么

一个**底层能力**（被调用者）：把既有文件的当前内容复制到备份存储根（store）下，形成一份**可跨会话恢复**的改前副本。

它不感知调用方是谁、不感知工作流、不引入工作流概念；调用方（项目规则、方法论层、全局约束）负责在正确的时机调用它，并传入正确的绑定值。

## 何时调用

- **修改或删除任何既有文件之前**——每次一次；
- **新文件无需调用**；
- 上游流程需要更早的基线时，可在流程开始处调用一次。

调用失败或机制不可用时的处理原则：**拒绝工作，而不是硬工作**——停止修改，先把机制修好。

## 用法

```bash
# 建改前备份（可一次备份多个文件）
change-backup snapshot --file <绝对路径> [--file <绝对路径>…] --store <绝对路径> --anchor <绝对路径>

# 只读查询：列出某文件的全部快照（按文件名时间戳降序）
change-backup list --file <绝对路径> --store <绝对路径> --anchor <绝对路径>

# 恢复（默认只打印将做什么；--apply 才写，且执行前会先备份当前文件）
change-backup restore --file <绝对路径> --store <绝对路径> --anchor <绝对路径> [--snapshot <快照名>] [--apply]

# 裁剪（默认只报告；--apply 才删；永不删最新一份）
change-backup prune --store <绝对路径> [--keep <份数>] [--apply]

# 机制自检（启动器原生实现，无需任何运行时）
change-backup selfcheck
```

参数细节一律以 `change-backup <子命令> --help` 为准（由 argparse 生成，本文不重复维护参数表）。

## 契约要点

| 要点 | 规定 |
|---|---|
| 布局 | `<store>/<文件相对 anchor 的路径>/<时间戳>`；时间戳即文件名 |
| 时间戳 | 本地时间 `YYYYMMDD-HHMMSS`；同秒重复追加 `-01`/`-02`…（保持字典序单调） |
| 保留 | 每个文件保留最新 **10** 份；`snapshot` 成功后自动裁剪；永不删最新一份 |
| 恢复判据 | 按**文件名时间戳**降序取第一份（不依赖文件修改时间） |
| 锚绑定 | 一个 store 只服务一个 anchor：首次写入时记录锚；此后不一致即拒绝 |
| 原子性 | 先写临时文件 → 校验字节数与 sha256 → 原子改名；失败不留半成品 |
| 参数 | `--store` / `--anchor` / `--file` 一律**绝对路径**；无默认值、不推导、不依赖 cwd |
| 失败 | 缺参、文件不存在、文件不在 anchor 之下、锚不一致、无可用运行时 → 报错退出，绝不静默降级 |

退出码：`0` 成功；`1` 失败（fail-closed）；`2` 幂等命中（同一秒内同内容已有快照）。

## 启动器

`scripts/` 下提供两个零依赖启动器（`change-backup` = bash；`change-backup.ps1` = PowerShell）与唯一实现 `change-backup.py`。

启动器按 `uv` → `python3` → `python` 探测可用运行时（以「实际执行 `--version` 成功」为判据）；全部不可用时报错退出。`selfcheck` 由启动器原生实现，因此即使没有任何运行时也能给出诊断。

## 边界

- 本机制只处理**可恢复的改前留痕**；其它形式的快照不在本机制范围内，也不在本机制中被描述。
- 本机制不涉及版本控制系统的配置：备份是否入库由项目自行决定与配置。
- 本机制不感知调用方、不引入工作流概念；「何时调用」由调用方文本规定。
- 如果同一存储根需要服务两个不同的相对路径基准，属于配置错误：请由项目层一次性调整基准，而不是为个别文件更换基准。
