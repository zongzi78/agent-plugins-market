# 全局约束接入说明（change-backup）

> 用途：AI-SDD 插件的接入说明之一，面向希望**全局约束**也能使用改前留痕的使用者。
> 发布位置：插件包根（与 `README.md` 平级）。
> 重要：**机制语义不在这里**——布局、命名、时间戳格式、保留份数、恢复判据一律以 `skills/change-backup/SKILL.md` 与 `change-backup <子命令> --help` 为准。

## 一、怎么用

1. 确认已安装 AI-SDD 插件（`change-backup` 技能随之可用）；
2. 打开你的全局约束文件（如 `~/.codex/AGENTS.md`）；
3. 找到其中描述备份/留痕的一节（通常叫「版本管理与留痕底线」），**用第二节的片段整体替换它**；
4. 保存即可——不需要在项目里再写任何配置。

## 二、可复制片段（整体替换旧的备份/留痕一节）

```markdown
## 版本管理与改前留痕

原则：任何修改都应可回滚。

启用条件：
- 有可本地提交的版本控制（如 git）→ 由版本控制提交留痕，不启用改前留痕；
- 无可本地提交的版本控制（如 SVN 工作树、裸目录）→ 修改或删除**任何既有文件**之前，必须经 `change-backup` 技能完成改前留痕；新文件无需留痕；
- 若当前工作空间已有生效的留痕约定（项目规则文件），以该约定为准；本节默认值仅在**没有任何工作空间级约定**时生效。

默认绑定值（均为绝对路径）：
- `--store`：`<工作空间根>/.backups`
- `--anchor`：`<工作空间根>`（即 agent 的工作目录）

适用范围：本规则只覆盖当前工作空间（agent 的工作目录）内的文件；**工作空间外的文件默认不修改**，经用户明确授权可以修改，但**不为其留痕**——其可回滚性由用户自行确认。

底线：
1. 改前确保可回滚：编辑既有文件前，先确认项目存在可回滚手段（版本控制提交 / 改前留痕 / 文件历史）。
2. 高风险操作前必留痕：删除、覆盖、批量替换、格式化等不可逆或高代价操作，执行前必须留有可回滚副本。
3. 改前留痕数据不入库：留痕数据不得提交进任何版本库。
4. 机制不可用时**拒绝修改**：留痕失败或机制不可用即停止，不得手工替代或跳过。
5. 仓库只建在项目边界：需要长期历史但无版本控制的项目，在项目根决策（git init / 纳入 SVN / 明确接受无留痕），需用户确认；不因单个文件或一次性修改新建仓库。
6. SVN 工作树内禁止 `git init`（避免双 VCS）；最终提交由人类完成。
7. 单一机制负责：同一文件、同一次编辑只由一个机制负责留痕。
```

## 三、为什么这么写

- **只写要求 + 默认值 + 底线**：机制细节都在技能里，改一处即生效，不会与技能定义漂移；
- **让位条款**：AI-SDD 工作空间自带工作空间级约定（store 用 `.ai/backups/`），全局默认值只在该约定不存在时生效——两套规则因此不打架；
- **措辞不点名任何具体文件**：全局约束不感知工作空间级资产；
- **默认值写在这里而不是让项目声明**：装好即用，零配置。

## 四、注意

- 技能不可用时**拒绝修改**（底线 4），不是"手工兜底"；
- 本文件随插件发布，是上述片段的唯一来源；**不要在项目里再抄一份**。
